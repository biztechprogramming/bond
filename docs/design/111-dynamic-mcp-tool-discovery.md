# Design Doc 111: Dynamic MCP Tool Discovery

**Status:** Implemented
**Author:** Bond Team
**Date:** 2026-04-28

## Problem

MCP tools from connected servers are not surfaced in the `/agents/tools` API
or enumerated in the agent context/help prompt. The `agent.tools` list only
contains native tool names, so frontends and agents have no visibility into
which MCP methods are actually available at runtime.

## Goals

1. **`agent.tools` stays native-only** — no MCP tool names stored there.
2. **`/agents/tools` returns native + live MCP tools**, grouped by source.
3. **Context/help prompt enumerates discovered MCP methods** per server,
   not just server names.
4. **Shared helper** (`mcp.discovery`) used by both the API and context builder
   to avoid duplicating discovery logic.
5. **Regression tests** ensure MCP tools appear in API and context output.

## Design

### Shared Discovery Helper — `backend/app/mcp/discovery.py`

A single module that:

- Calls `MCPManager.list_tools()` (host-side) or reads
  `MCPProxyClient._tool_cache` (worker-side) to get the current MCP tool list.
- Formats results into a unified list of `MCPToolInfo` dicts with fields:
  `name`, `server`, `mcp_name`, `description`, `parameters`, `source`.
- Provides `format_mcp_tools_for_context()` to generate a prompt section
  enumerating every tool grouped by server.

### API Changes — `GET /agents/tools`

Returns `{"native": [...], "mcp": [...]}` where `mcp` entries include
`server` and `source` annotations. Backward-compatible: callers that only
read the flat list still work via a top-level merged list.

### Context Builder Changes

Replaces the current "Connected external services: server1, server2"
summary with a per-tool enumeration generated by the shared helper.

### What Does NOT Change

- `agent.tools` in the DB — remains native tool names only.
- MCP tool registration in the `ToolRegistry` — still happens via
  `refresh_tools()` / `register_proxy_handlers()` at loop startup.
- MCP CRUD endpoints (`/mcp/servers`) — unchanged.

## Testing

- `test_mcp_discovery.py` — unit tests with a mock MCPManager that
  returns fake discovered tools, verifying:
  - `discover_mcp_tools()` returns correctly formatted entries
  - `format_mcp_tools_for_context()` produces per-tool enumeration
  - `/agents/tools` endpoint merges native + MCP tools
  - Context builder includes per-tool MCP enumeration

## Rollout

Ship behind existing MCP infrastructure. No migration needed — the
discovery is purely runtime and read-only.
